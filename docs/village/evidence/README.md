## Earlier milestones

Generated from the actual village modules with `python3 scripts/village/preview_qa.py --port 3011` (activity exits used port 3012; villager dialogue/approaches used port 3013). See the [build ledger](../../../VILLAGE_BUILD.md) and [design QA](../../../design-qa.md) for limitations. The harness compiles into a temporary directory and serves locally; it is not a production route. Its named outputs overwrite prior captures. Scene captures, motion and profile describe the bridge/environment feedback pass; activity-exit and villager evidence are later follow-ups. None of these files changes the approved art target.

- [Entrance](entrance.png), [cottage](cottage.png), [bridge deck](bridge.png), [rain](rain.png), [dusk](dusk.png), [hearth](hearth.png), [camera up](camera-up.png), [camera down](camera-down.png), [rear valley](camera-rear.png), [bridge profile](bridge-side.png): final renderer captures, 1280×720 canvas, high tier, no DOM overlays. First checked in Firefox, then refreshed in the in-app browser after the bridge rebuild. They include the solid arch, inward-facing hearth seats, clouds and full camera pitch range.
- [motion.webm](motion.webm): final 16.78-second scripted walk/run/sprint/jump sequence and bank-to-bank bridge crossing in both directions, VP9 1280×720 with 48 kHz stereo Opus. Captures the master bus before the output compressor. Observed events: 43 footsteps, two takeoffs, two landings, minimum energy 46. Perceptual sound synchronization remains unreviewed.
- [profile.json](profile.json): final 120.03-second repeated entrance/postbox path traversal, detailed tier, after the bridge/environment feedback fixes and before the activity-exit follow-up. Mac16,12, arm64, 16 GiB; 1280×720 drawing buffer, DPR 1. Mean 22.00 ms (about 45 fps), p95 33.4 ms. Mean/p95 are requestAnimationFrame intervals, not GPU timer queries. End-of-profile counts: 145 calls, 4,552,368 triangles, 67 geometries, 65 textures; calls include bounded shadow refresh. Desktop activity/background conditions were uncontrolled. Sustained 60 fps is not established; no claim of target-phone or 1080p performance.
- [Piano](audio-piano.mp3), [lo-fi](audio-lofi.mp3), [jazz](audio-jazz.mp3): earlier systems-milestone previews, unchanged by the feedback pass. Each contains 120 seconds of production score/instruments plus a five-second release tail. Seeds 62025/62042/62059; score version `village-phrases-1`; music 0.6, master 0.65. 22,050 Hz stereo WAV rendered offline, then encoded to 128 kbps MP3 without normalization. Source WAVs were retained temporarily in `/tmp/cosy-village-audio-masters/`; reproduce them through the harness if no longer available.
- [audio-measurements.json](audio-measurements.json): earlier preview sample peak and RMS on the WAVs, not true peak or integrated LUFS. Post-balance peaks approximately −19.05/−20.66/−21.09 dBFS, RMS −40.81/−40.97/−41.15 dBFS; maximum 7/8/8 simultaneous music voices. Subjective quality and long-session listening remain unverified.
- [audio-lifecycle.json](audio-lifecycle.json): nine passing Firefox 156 browser assertions, including the legacy listener position/orientation path: sample decoding, starting muted, unmute, transient cap, leaving shelter in simple view, overdue event discard, stop/suspend, reported sample failure. Repeated disposal was also executed successfully after its fix.
- [audio-output.json](audio-output.json): actual Firefox 156 audio graph check, all samples decoded, context running, peak 0.04446 and RMS 0.00707. Uses Firefox's legacy listener methods. This proves non-silent graph output, not headphone listening.
- [scene-audit.json](scene-audit.json): four residents, two moving during the final five-second sample, twelve birds, clear bridge planting and clear main-road access past the hearth. Residents pause at route endpoints and for the player. Its instantaneous 46 fps/54-call sample is distinct from the full traversal profile above.
- [villager-approach.json](villager-approach.json): 20 deterministic browser checks for all four residents, frame-rate agreement, personal space, return behavior, obstacle/water rejection and invitation suppression. [villager-approach-runtime.json](villager-approach-runtime.json) samples the real engine/rig/dialogue once per second over 18 seconds; use **Watch Pip approach** in the local QA harness. These are behavior observations, not a new performance benchmark.
- [villager-dialogue.json](villager-dialogue.json): 28 browser checks for the subsequent overhead-dialogue feature, using production dialogue modules and real DOM layout. Includes all four voices, projection/occlusion, language changes, portrait bounds, activity suppression and tea-garden return. Run **Check villager dialogue** in the local QA harness; visual observations and device limits are in the [dialogue ledger](../../../VILLAGE_BUILD.md#2026-09-25-villager-dialogue). Earlier renderer-only captures do not include these DOM bubbles.
- [activity-exits.json](activity-exits.json): later Firefox check using real world colliders. Reproduces the former pond/nook traps, then verifies clear arrival coordinates, four-direction walking and restored 3.8 m camera distance after all six exits. Desktop/mobile/simple-view button and focus observations are recorded separately in the [activity-exit ledger](../../../VILLAGE_BUILD.md#2026-09-25-activity-exit-fix).
- [profile-systems.json](profile-systems.json): retained earlier 120-second systems-milestone profile for comparison; it is not a controlled before/after benchmark.

The music uses Alexander Holm's Salamander Grand Piano samples, CC BY 3.0, with original procedural arrangements and synthesis.
