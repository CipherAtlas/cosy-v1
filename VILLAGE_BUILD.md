## 2026-09-29 local chat admin

The shared Worker's secret-protected `/admin/chat` API lists current-hour messages, removes one by stable message ID, or clears the current hour. Older saved messages gain IDs without changing their sender or text. Removal updates stored chat and broadcasts a `chat_sync` snapshot to connected visitors; the updated client removes entries and matching overhead bubbles. Clear all requires the displayed hour as `If-Match`, so a stale tab cannot clear a new hour. Normal visitors cannot use these actions through their WebSocket messages. It checks Host, Origin and a local session token on mutations. The page has Refresh, Remove and Clear all controls and refreshes every five seconds. It is outside the public static export.

## 2026-09-29 point-light shader performance investigation (local)

A live Firefox 156 report from an M4 MacBook Air near the bridge in Golden hour showed 10 FPS at 1920×965, Detailed graphics, 271 draws and 2.77 million triangles; the visitor also saw intermittent drops near 2 FPS. An isolated native Firefox 156 preview on the same machine reproduced a bridge view with about 2.6 million triangles but stayed smooth in ordinary animation. The 2 FPS episode was not reproduced. Removing the sky, vegetation or shadows in short local runs did not isolate a Golden-hour cause. Night enabled 14 village lamps and four spirit lights and caused a much larger lighting cost.

The runtime now skips each point light's fragment lighting calculation outside that light's existing cutoff radius, where Three.js attenuation is exactly zero. This includes the always-on hearth light in Golden hour and nearby lamps at night. The shader change itself did not alter lights, geometry, shadow quality, drawing-buffer size, mood, interactions or saved layout; the later Safari pass above limits active night lights and can reduce Detailed's drawing buffer. The Settings performance report now records the selected weather, shader-program count, lowest two-second FPS, longest frame gap and longest render-submission call after a four-second warmup. The worst values remain available after switching tabs for the rest of that village visit. Render-submission time is CPU/driver wall time, not a GPU timer.

Focused local Firefox 156 runs at 1920×965 with a forced `gl.finish()` probe showed variable Golden-hour submission times; the closest sequential comparison was 8.0 ms before and 7.2 ms after. Night was consistently more expensive before the change; the closest sequential comparison was 15.4 ms before and 9.3 ms after. `gl.finish()` changes frame pacing, so these figures are a relative probe rather than user-facing FPS. Golden-hour and night still images rendered with no WebGL error and retained the same static scene; moving residents and subpixel timing accounted for small image differences. `npm run typecheck`, the root-path production static export with the existing shared-world URL, and `git diff --check` passed.
